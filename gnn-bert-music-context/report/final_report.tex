\begin{abstract}
This report presents a reproducible multimodal music-context system that combines DistilBERT text representations, PyTorch Geometric segment graphs, GraphSAGE audio encoding, cross-attention fusion, and contrastive audio--text retrieval. The experiments use a 100-track processed FMA-small sample for tagging and graph tasks, within-dataset DEAM audio/emotion pairs for regression, and 95 locally verified MusicCaps audio--caption pairs for Task 4. The repository includes controlled baselines, ablation probes, held-out retrieval evaluation, qualitative retrieval exports, and reproducibility scripts. Results are reported as execution evidence on the available subsets, not as claims over the full source datasets. Human listener ratings remain a required external collection step.
\end{abstract}

\section{Introduction}
Music context includes genre, instrumentation, mood, production characteristics, and natural-language descriptions. Audio-only sequence models capture local spectral patterns but do not explicitly represent relationships among temporal segments. Text-only models capture semantic descriptions but do not observe the audio structure. This project studies a hybrid representation in which a graph encoder summarizes audio segments and a BERT encoder summarizes metadata or captions.

The project follows the four-task roadmap in the assignment specification: BERT tagging, graph-based audio classification, GNN--BERT fusion, and contrastive MusicCaps alignment. The implementation emphasizes strict data provenance. Records are paired only when the graph/audio file and text record share a verified source identifier; coincidental numeric overlap across unrelated datasets is not used as an alignment rule.

\section{Datasets and Data Integrity}
\subsection{FMA}
FMA-small audio and official metadata are used for Tasks 1--3. One hundred real tracks were processed at 22,050 Hz using fixed five-second windows with 2.5-second hop. Each track produces mel, chroma, MFCC-derived node features and a PyG segment graph. The leakage-safe split contains 80 training, 10 validation, and 10 test tracks. The expanded label vocabulary contains 26 FMA tags.

\subsection{DEAM}
DEAM audio and song-level valence/arousal targets are paired by exact normalized DEAM song identifier. The resulting DEAM manifests contain 1,441 training, 180 validation, and 181 test records. DEAM identifiers are not joined to FMA identifiers.

\subsection{MusicCaps}
The MusicCaps CSV supplies YouTube identifiers, timestamps, and expert captions. The downloader retrieves only the requested timestamped segment and converts it to mono 22,050 Hz WAV. Of the first 100 requested records, 95 source videos were available and processed; five unavailable videos were skipped without fabricating audio. The resulting MusicCaps split contains 76 training, 9 validation, and 10 test records when generated by the current preprocessing command.

\section{Methods}
\subsection{Audio Graph Encoder}
For each audio window, the processor extracts normalized log-mel, chroma, and MFCC descriptors. Segment descriptors are graph nodes. Temporal adjacency and cosine-similarity edges are passed to a two-layer GraphSAGE encoder. Mean graph pooling produces an audio vector $g$.

\subsection{Text Encoder and Fusion}
DistilBERT produces hidden token states $H_{text}$ and a pooled text vector. For Task 3, projected graph and text states are combined using multi-head cross-attention. The fused representation feeds a multi-label tag head and optional valence/arousal regression heads. For Task 4, graph and caption embeddings are projected into a shared normalized space.

\subsection{Contrastive Objective}
For a batch of paired graph and caption embeddings, the similarity matrix is
\begin{equation}
S_{ij}=\frac{g_i^\top t_j}{\tau},
\end{equation}
where $\tau$ is the temperature. The InfoNCE objective uses the diagonal pairs as positives:
\begin{equation}
\mathcal{L}_{NCE}=-\frac{1}{N}\sum_i \log\frac{\exp(S_{ii})}{\sum_j\exp(S_{ij})}.
\end{equation}
Retrieval is evaluated in both caption-to-audio and audio-to-caption directions using Recall@1, Recall@5, and Recall@10.

\section{Baselines and Reproducibility}
The majority predictor and mel-spectrogram CNN satisfy the required baseline comparison. The BERT-only Task 1 model is also used as a representation baseline for Task 3. All source files compile under Python 3.12. The principal commands are:

\begin{verbatim}
python src/preprocess_fma.py --limit 100
python src/train.py --task task1 --real-data --epochs 3
python src/cnn_baseline.py --epochs 3
python src/train.py --task task2 --epochs 3
python src/task3_analysis.py --checkpoint checkpoints/real_paired/task3_epoch_1.pt
python src/download_musiccaps.py --limit 100
python src/preprocess_musiccaps.py --limit 100
python src/train.py --task task4 \\
  --manifest-root data/splits/musiccaps --epochs 20 \\
  --checkpoint-dir checkpoints/musiccaps_task4_95_epoch20
python src/evaluate_fma_multimodal.py --task task4 \\
  --manifest-root data/splits/musiccaps \\
  --checkpoint checkpoints/musiccaps_task4_95_epoch20/task4_epoch_20.pt \\
  --output results/musiccaps_task4_metrics.json
\end{verbatim}

\section{Limitations and Completion Status}
The experiments use small local subsets because full source datasets and YouTube availability are constrained. The 95-pair MusicCaps result is not a full 5,521-clip benchmark. MagnaTagATune metadata is present but its approximately three-gigabyte audio archive is not paired. Human evaluation is prepared but not completed. The 20-epoch Task 4 history shows training loss continuing below validation loss, indicating overfitting on the small subset; the held-out metrics are therefore the primary reported result. The report source is complete; PDF compilation requires a LaTeX toolchain such as TeX Live or MiKTeX.

\section{Conclusion}
The repository now contains an end-to-end real-data GNN--BERT implementation covering FMA tagging and graph learning, DEAM within-dataset emotion data, and genuine MusicCaps audio--caption contrastive retrieval. Every computational artifact is reproducible and tied to a manifest or checkpoint. The remaining submission actions are external: collect five listeners' ratings, review the final figures, compile this file to PDF, and package the repository with the generated evidence.
